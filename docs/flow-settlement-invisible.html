Deep Sea Hunter

Satu kalimat: user main seperti biasa. Yang dia sadar cuma tiga momen: approve sekali + storage sekali di awal, dan withdraw di akhir. Sisanya transaksi on-chain jalan di belakang layar.

Sudah dibangun Belum dibangun Belum diputuskan Yang user lihat Di belakang layar (on-chain)

0.Setup — sekali sajaSUDAH · SLICE 2

YANG USER LIHAT
  • Connect wallet (Meteor / MyNearWallet / HERE) → verify, sign 1 pesan
  • Tombol ENABLE INVISIBLE SETTLEMENT → approve 1 kali di wallet
  • Storage deposit 1 kali (0,009 NEAR)
DI BELAKANG LAYAR
  • Wallet terikat ke akun game (players.wallet_account)
  • Function Call key ditambah ke akun user — scope: kontrak merchant, method mint_catch / mt_transfer / mt_batch_transfer, allowance 0,25 NEAR (gas saja)
  • Storage didaftarkan di kontrak merchant
Ini satu-satunya setup yang terlihat. Setelah ini tidak ada popup lagi.

1.Dive & catchSUDAH

YANG USER LIHAT
  • Dive → tembak → “CAUGHT Clownfish”. Sudah, itu saja.
DI BELAKANG LAYAR
  • Server terbitkan catch receipt (UUID) → simpan di Postgres
  • Populasi habitat −1, ikan masuk inventory

2.Mint — tanpa sadarSUDAH · SLICE 2

YANG USER LIHAT
  • Tidak ada apa-apa. Di tab chain cuma tertulis “last catch settled · hash…”.
DI BELAKANG LAYAR
  • Frontend minta tanda tangan server: POST /api/near/receipt-signature
  • Panggil mint_catch pakai session key → token fish:{receipt_id} mint ke akun user
  • Hash tercatat di riwayat settlement (tab chain)
Kalau gagal (offline, storage kurang): receipt antre di HP, dicoba lagi otomatis pas buka game berikut. Game tidak pernah nunggu settlement.

3.Sell ke merchantBELUM · SLICE 3

YANG USER LIHAT
  • Klik SELL → +18 CR. Sudah.
DI BELAKANG LAYAR
  • CR pindah merchant → player (ledger Postgres, off-chain)
  • Session key panggil mt_transfer: token fish:{receipt_id} → merchant desk
  • Event mt_transfer tercatat di Explorer — “ikan X dijual si Y”
Jalur lama tetap ada terpisah: sell di tab NEAR pakai accept_purchase_order + klaim NEAR, perlu sign wallet. Itu bukan jalur invisible.

4.Jual / beli di toko (marketplace)BELUM · SLICE 3

YANG USER LIHAT
  • Penjual: listing ikan di toko, harga bebas
  • Pembeli: klik BUY → CR pindah, ikan langsung masuk inventory
DI BELAKANG LAYAR
  • CR pindah pembeli → penjual (atomik, Postgres), receipt pindah ke pembeli
  • Token on-chain tidak bisa langsung: kunci session penjual ada di browser penjual, dan penjual sedang offline
  • Transfer token antre — dieksekusi saat penjual buka game lagi (client penjual flush queue). Token nyusul, ikan sudah di tangan pembeli duluan.

5.Withdraw CR → NEAR — di sinilah user “ketemu” chainBELUM DIPUTUSKAN

YANG USER LIHAT
  • Layar withdraw → pilih jumlah CR → NEAR masuk wallet.
DI BELAKANG LAYAR
  • CR dibakar (off-chain) → NEAR dikirim dari treasury
  • Rate CR→NEAR + sumber NEAR belum diputuskan
Yang perlu diingat:
  • Guest tanpa wallet tetap main off-chain penuh — tidak ada akun NEAR untuk dituju tokennya.
  • Session key tidak bisa pindah NEAR, panggil kontrak lain, atau attach > 1 yocto. Allowance habis → grant ulang sekali.
  • Kontrak: merchant Testnet (dsh-merchant-v1.deepfish-owner.testnet).
  • Untuk juri: makin bagus invisible-nya, makin tidak ada yang kelihatan — yang ditunjukin itu riwayat hash di tab chain.
